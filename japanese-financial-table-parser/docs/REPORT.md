# Design and findings

## Objective and definition of correctness

Convert the supplied Japanese consolidated balance-sheet page to a table while
preserving row order, original Japanese labels, reporting-period assignments,
currency/units, displayed hierarchy, and numeric meaning. Correct extraction must
distinguish explicit dashes from blanks and preserve negative zero as evidence.
An arithmetic identity alone does not establish correctness.

The scope is one corrected, text-layer, assets-only page, with a documented route
for unsupported inputs. The page does not contain liabilities/equity, so the full
balance-sheet equation cannot be checked from this input.

## Implementation choices

Use the text layer with pdfplumber and its detected table-cell boundaries. This
avoids OCR for a document that already contains text, preserves source coordinates,
and handles a dash in the prior-year column without shifting the current amount.
NFKC supports interpretation without overwriting raw text.

Label indentation provides a display hierarchy. Row IDs plus page indices provide
identity; full paths distinguish repeated labels. Six section names and explicit
Japanese subtotal/net/depreciation patterns define the supported baseline. Errors
or unsupported relationships are surfaced rather than silently guessed.

The versioned JSON Schema documents raw/normalized strings, typed values, status,
negative-zero flags, hierarchy, periods, units, correction marker, printed versus
physical page numbers, source SHA-256, and PDF-point cell regions.

## Measured extraction result

Against the separately entered, visually checked reference: 43/43 labels and paths,
86/86 period cells (72 numbers, 2 dashes, 12 blanks), and 10/10 negative markers
match. The same assistant authored the implementation and reference. Independent
human annotation is pending; this is a development-set measurement, not an
independent held-out evaluation. See `REFERENCE_AUDIT.md` for the exact provenance.

## Validation findings

Twenty potential arithmetic checks cover section totals and net values. Under the
default policy, 7 are exact, 11 have nonzero residuals within the declared bound,
and 2 cannot be evaluated because a dash is not assigned a numeric value. None
exceeds the bound. Optional dash-as-zero analysis is clearly labelled conditional.

Residuals include current-assets totals (+3/+2 thousand yen), prior fixed assets
(+2), current total assets (+1), and some net amounts (-1). They are consistent
with presentation rounding or truncation, but the cause is unverified. The validator
never changes source amounts. The bound is derived from an explicit less-than-one
displayed-unit error assumption per quantity, not fitted to force sample success.

## Robustness and routing

Ten synthetic scenarios exercise the real PDF-to-routing path. Whole-page
translation and moving a number inside its cell preserve extracted content. An
image-only scan requests OCR; an unknown readable section requests structural
review; a column collision requests extraction review; a digit transposition and
a removed negative sign request human review.

A one-unit error and two compensating amount errors remain accepted. These are
intentional demonstrations of diagnostic blind spots. All ten expected routing
outcomes are met, including those accepted corruptions; the result is not an
error-detection accuracy claim. Thirty-two automated test cases pass.

## Extension and remaining work

For real deployment, evaluate held-out filings, add an alternate text extractor,
support broader date/unit/section patterns, and implement OCR/VLM adapters that
produce the same schema and retain evidence. Re-run structural and arithmetic
diagnostics after each extraction path. Add human-review feedback and measure
coverage, error detection, latency, and cost on representative documents.

The current solution stops at routing for scans and unsupported formats. It does
not claim a complete solution for arbitrary financial PDFs. The actual complete AI
conversation must accompany submission separately; no summarized replacement log
is generated by this project.
